# Examples

Two small shops, one on Laravel 13 and one on Symfony 7.4, both on PostgreSQL. Each
records order events with `ianfoxdev/outbox`, runs the relay from this repository and
reads the events back from Kafka.

| | Laravel | Symfony |
|---|---|---|
| Writes through | Eloquent model, `DB::transaction()` | Doctrine DBAL, `Connection::transactional()` |
| Outbox table from | the migration published by `vendor:publish --tag=outbox-migrations` | the migration generated by `bin/console outbox:migration` |
| Consumer | `php artisan orders:consume` | `bin/console app:consume-orders` |
| Port | 8000 | 8001 |

Both expose the same endpoints:

- `POST /orders` with `customer` and `total` creates an order and records `OrderPlaced`
  in the same transaction. With `fail=1` it throws after the event was recorded, the way
  a timed out payment call would, and answers 503: the order and the event are rolled
  back together.
- `POST /orders/{id}/pay` locks the order row, marks it paid and records `OrderPaid`.
  Locking first is what keeps the events of one order in commit order, see
  [ADR 0002](../docs/adr/0002-single-active-relay.md).

## Run

```bash
cd laravel   # or symfony
docker compose up -d --build --wait
docker compose exec app vendor/bin/phpunit
```

The tests check that `OrderPlaced` and `OrderPaid` of one order arrive in Kafka in that
order, in one partition, with the CloudEvents headers and `ce_id` equal to the event id
in the table; that a failed checkout leaves neither an order nor an outbox row; and that
paying twice records one `OrderPaid`.

By hand:

```bash
curl -X POST localhost:8000/orders -d customer=ann -d total=1999
curl -X POST localhost:8000/orders/1/pay
docker compose exec app php artisan orders:consume
```

```
p1@0 key=1 OrderPlaced 01a0f1a3-4474-7285-9c5f-46d3e63c479d {"order_id":1,"customer":"ann","total":1999}
p1@1 key=1 OrderPaid 01a0f1a3-44af-76ca-85ea-867e73125b6b {"order_id":1,"total":1999}
```

For Symfony use port 8001, a JSON body and `bin/console app:consume-orders`.

```bash
docker compose down -v
```

## Things that bite in tests

- `RefreshDatabase` in Laravel, or a DAMA-style transaction wrapper in Symfony, runs
  each test inside a transaction that is rolled back at the end. Nothing is ever
  committed, so the relay never sees the events. These tests commit for real.
- The consumers skip events whose `ce_id` they have seen. Delivery is at-least-once: a
  relay that fails over in the middle of a batch sends it again. A real consumer keeps
  the ids in a table in the same transaction as its own writes.

## How it is wired

`infra.yaml` holds Postgres, Kafka and a one-off container that creates the
`order.events` topic. Each example's `compose.yaml` includes it and adds the app, built
from `php.Dockerfile` (FrankenPHP with `pdo_pgsql` and `rdkafka`), and the relay, built
from `../../relay`. The whole repository is mounted into the app and `composer.json`
takes `ianfoxdev/outbox` from `../..`, so the examples always run the code of the
current checkout. The relay starts after the app has run its migrations.
